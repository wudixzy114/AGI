Project 4 · 从根本上不同于 Transformer

一个原生快权重内核
与它挂载的分层记忆系统

Project 3 证明:在冻结的 Transformer 上外挂记忆,值能被写入/寻址/读出,却无法被当作算子使用(ref_acc = 0.10 = 瞎猜)。Project 4 换掉架构本身——一个从零训练、记忆读即原生算子的递归内核——把同一个指标从 0.10 推到 1.00。

矩阵状态 S ∈ ℝ^{d×d} 无注意力 · 无 KV cache 多时间尺度 γ=[0,.7,.95,.99] 5-seed 1.000 ± 0.000
01

缘起 — Project 3 撞的那堵墙

在冻结 Transformer 上,记忆的前三个环节都成立,唯独"使用"塌成瞎猜。这不是没调好——冻结的计算图里根本没有"消费一个注入隐向量作为算子"的接口。可观测 ≠ 可用。

02

内核 — 为什么它不是 Transformer

每一层携带一个固定大小的矩阵状态 S(快权重 / 线性注意力式联想记忆)。序列由一个递归 scan 逐 token 消费:用外积写入 S,再用 r = S·q 读回。没有 token 间注意力,没有 softmax over sequence,没有越堆越大的 KV cache。

输入 token 流
整个会话 = 一条流 [BOS, slot, R/LIT, arg, ops…, =, ans] × T
共享的"记忆"就是内核自己的递归状态,不是外挂模块
embed
FastWeightCell · 逐 token 递归
# 从隐状态 h 投影(k,q 做 ℓ2 归一化) k, v, q = W_k·h, W_v·h, W_q·h ; β = σ(W_β·h) S ← γ·S + β·(v − S·k)·kᵀ # delta 规则:先擦旧关联再写新值(覆盖) r = S·q # 读 = 算子,在 cell 内部算出 out = h + W_o·r # 读直接加回残差流
USE 为何原生: 读 r = S·q 在 cell 内部算出并加回残差流——不存在"把外来向量注入冻结栈"这一步,而那正是冻结 Transformer 消费不了的东西。
× N 层(不同 γ)
readout head
= 位置的隐状态 → mod-N 数字 logits
唯一的任务专用头;其余一切从随机初始化训练
固定状态

不随长度膨胀

状态永远是 d×d 矩阵,无论会话多长。对比 Transformer 的 KV cache 随上下文线性增长。

联想召回

精确、不模糊

写 v⊗k、以 q≈k 读回可精确恢复 v——回应"大海捞针"衰减问题;对角 SSM 会把值糊掉。

可并行

结合律 → chunk scan

递归是结合的 → 存在分块并行形式(chunked linear attention)。本 demo 跑串行 scan(T 短、模型小),设计本身可并行。

03

分层记忆 — 承重墙,不是装饰

L 层堆叠,衰减率 γ 铺开成一个梯度。这不是可选项:慢层就是跨问题的记忆库,快层就是问题内的工作记忆。右列是多时间尺度探针实测的"存储值可解码性"(延迟 Δ=1 时)——层级不是断言,是量出来的。

Layer 0 γ = 0.0
工作记忆 · 只记最近 token → 问题内的模运算链
0.15Δ1 探针
Layer 1 γ = 0.7
短缓冲 · 保留约 1 步后快速衰减
0.95Δ1 探针
Layer 2 γ = 0.95
中期保持 · 跨几个问题
0.68Δ1 探针
Layer 3 γ = 0.99
会话级存储 · 跨整个会话持有 slot 值
1.00全 Δ 平坦
长会话验证: session_len=10、延迟到 Δ=9,慢层 γ=0.99 的探针在每一个延迟都是 1.00 —— 固定大小的矩阵状态不随距离模糊。这就是当初选联想式快权重矩阵、而非对角 SSM 的理由。
04

实验流 — 可证伪的任务与三个臂

沿用 Project 3 的会话任务:引用问题 R0 …= 必须读 slot 0 的值,而这个值不在当前问题的 token 里 → 引用准确率直接衡量"记忆使用"。难度用 session_hops 扫;hops=0 纯召回是无算术混淆的最干净判据。

K0

断读对照

read_enabled = False # 快权重照常写 S # 但 r 永远置零

因果对照:切断读通路。预测 ref_acc → chance。

K1

仅答案监督

loss = CE(answer) # 无任何读监督 # USE 能否自己涌现?

测试:使用能否只从结果监督里涌现。

K2

+ 接地读监督

loss = CE(answer) + CE(read → 存储值) # 引用处的读须解码出值

最接地的臂;给读通路一个直接的训练信号。

最强单点

5-seed 1.000 ± 0.000

K0 = 0.104 ± 0.012。饱和、铁稳——不像 Proj-2b 的 OOD 幅度是 seed 敏感的。

诚实边界

hops2 = 算术墙,非记忆失败

从零学 mod-N 是 grokking-slow(arith uniform 同样卡 chance)。所以 hops=0 才是无混淆判据。curriculum 能救算术:0.99→0.88 分布内,0.59 OOD。

通路: Proj-3 里值能被存储、寻址、探针解码却不可用;Proj-4 里当记忆读是原生算子,使用立刻且彻底(chance→1.0)、可因果归因、且时间尺度层级可观测。冻结性在 Proj-3 是承重墙;拆掉它——靠造对内核而非推错内核——负面结果就翻正了。

基础设施 — 调度器 + 看板

这些内核任务只占 ~4GB/183GB 且受启动开销限制,手写的 &+wait 批次浪费 GPU。两块可复用基础设施为后续所有项目服务。

scheduler/

资源感知调度器

按实测显存余量装箱并发(180GB 空闲 → 8 任务齐开),无状态存活判定(pgrep + metrics.json,重启不重复启动),崩溃有 grace + 重试上限。改 jobs_*.json,不改代码。

dashboard/

数据驱动看板

按 metrics.json 的指标形状自动出图(会话柱状 + 时间尺度扇形 / 深度-精度曲线),synthDash 让新老数据都有规范标题,深色模式,失败保留上次状态永不白屏。
