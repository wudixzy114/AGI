# 大模型记忆机制与输出降维：一份心路历程

> 这不是论文，也不是讲稿。这是我（谢宗羽）从 2026 年春天开始，围绕"为什么大模型不是 AGI"这个问题，
> 一路想下去、试下去、撞墙、再想下去的真实记录。
>
> 2026-07-13 我和 Gemini 做过一次长对话，把当时还比较模糊的思考捋成了可工程化的方案。
> 那次对话的原文已经散落（也因为我当时一边想一边说，结构比较散），所以这里把它重写成一份连贯的叙述。
> 后续的实验发现（Project 1–5）已经验证了其中一些想法，也推翻了一些。
> 这份文档是**做实验之前的思考**——是我怎么从两个"凭直觉冒出来的问题"，走到"必须亲手做一个可证伪的小模型"这一步的。

---

## 一、起点：两个当时没人问我的问题

我现在回头看，自己真正开始动脑想 AGI，不是因为读了哪篇论文，而是因为**两件看着不爽的事**。

**第一件：满 vs 留白。**

我们把 Transformer 的 QKV 权重当成"长期记忆"来看待。训练一完成，权重就基本不动了。
这意味着**整个模型从结构上就是"满"**的——所有容量都被预训练塞满了，没有"空着等我写"的区域。

那么短期记忆呢？个性化呢？事实性知识呢？现在工业界的所有做法——LoRA、RAG、Context Window、记忆外挂——
本质上都是**在"满"上面做文章**。LoRA 是"在已满的权重上加一个低秩扰动"，RAG 是"在外部再叠一层查表"。

我当时直觉上觉得：**一个真正能"成长"的系统，应该在结构上有一块"留白"——不是改造已有的，而是本来就空着、专门用来被新经验写入的区域。**

**第二件：线性降维的损失。**

Transformer 内部是高维的浮点向量空间，概念是叠加态、网状的、几百几千维的。
但输出时，模型被压扁成一维的 Token 序列——一个字接一个字。

这意味着高维空间里的"多义性、模糊性、立体关联"，在输出第一个字的那一刻就被**坍缩**了。
模型内部可能同时在几个方向上思考，但吐出来第一个词之后，就只能沿着一条线继续往前推。
剩下的可能性在内部还在，但在文字层面已经死了。

我当时觉得：**这种"被迫降维"是表达能力的物理瓶颈。文字只是 AI 为了迁就人类而采用的一种"低级降维接口"——它本身应该可以被绕过。**

## 二、第一次哲学化：道德经给了我一记闷棍

我把这两个直觉拿给 Gemini 讨论。它给了我很多技术参考（fast weights、MoE、Prefix-Tuning…），
但真正让我停下来想的是它引用的那句《道德经》：

> **为学日益，为道日损。**

我突然意识到，我前面提的"满 vs 留白"和"降维损失"，本质上讲的是同一件事的两面：

- 预训练阶段是**日益**——把人类几千年的语料、代码、科学、垃圾话全堆进参数里，参数量越大越好。
- 推理/提炼阶段应该是**日损**——把这些堆积的"学"压缩、蒸馏成"道"，最后几 B 参数的"提炼物"反而可能比几百 B 的原始权重更"智能"。

这跟现代 AI 工程的很多做法是反着来的。我们现在追求"千亿参数 + 知识密集"，
但很少有人认真想过：**真正智能的部分，可能远小于我们塞进去的知识。** 知识可以外挂（RAG），
但"道"必须内化——而"内化"本身就是一种"日损"。

由此引出第二个让我震动的反思：

> **动态 MoE 的"冷启动死亡谷"——这不是技术缺陷，是我们的傲慢。**

想象一个家长，因为一岁的孩子不会解微积分，就剥夺他说话的权利，以后所有问题都只去问大学教授。
这就是目前 MoE 路由的逻辑——Loss 高的专家立刻被 Router 抛弃，再也拿不到梯度，再也学不会。

但**这不在于技术本身，而在于我们如何看待 AI**：
- 如果我们把 AI 当**工具**——必须 0.1 秒给出正确答案——那"留白"永远活不下来。
- 如果我们把 AI 当**需要成长的生命体**——那冷启动不是 Bug，是**婴儿期的必经之路**。

我后来在做 Project 1 时回头看这段话（"the growable 变 module is not inherently weak — it is fragile to *train*"），
发现**我所有的工程直觉在这里就已经埋下了**。

## 三、再进一步：通向 AGI 必须跨过的三道门

聊到这里我开始想：前面讲的"满/留白"和"降维损失"其实是**两个症状**，背后是**三个根本问题**。
这三个问题不解决，前面说的所有工程方案都只是修补。

### 1. 过程 vs 结果：到底什么是"智能"？

现代训练范式（监督学习 + RLHF）的本质是**唯结果论**——只要最后 Token 对了，Loss 就下降；错了就惩罚。
我们寄希望于数据量足够大，模型内部会"涌现"出正确的逻辑。

但**过程错了，碰巧结果对了**的事天天发生。
模型学会了"模仿正确答案的格式"，而不是"掌握推导过程"。这就是幻觉的根源之一。

如果 AGI 是真正的认知生命体，它必须**对过程有价值观**——
即使最后因为某个事实性错误导致结论全错，只要推理过程严密，也应该得到巨大奖励。
这就是后面 Project 1–2 里反复出现的"过程监督 > 结果监督"的根源。

### 2. 变 vs 不变：可塑性与稳定性的动态平衡

现在的模型，**训练时全盘皆变**（灾难性遗忘），**推理时全盘不变**（静态权重）。
LoRA 之类的外挂是缝补，但它们之间是物理隔离的，缺乏有机的协作。

神经科学里这叫"可塑性-稳定性困境"。要解决，需要一个**双系统**：

- **不变的道**——一个被绝对冻结的底座，只包含"不会过期的底层规律"：物理、形式逻辑、语法、因果推导。
  它的角色是"导师"，用底层逻辑约束动态模块的发散。
- **变的触手**——一个初始为空白的动态模块，专门吸收新知识、适应新用户、犯错、成长。
  它的角色是把环境信息翻译给底座。

两者通过**正交约束**协作——动态模块更新权重的方向必须与底座的核心特征向量保持**正交（垂直）**，
这样无论"触手"怎么野蛮生长，都不会破坏"道"。

### 3. 短期 vs 长期、部分 vs 整体：时空维度的有机流转

现在的长文本只是把上下文窗口拉长（短期强行当长期用），MoE 只是把模型切碎（整体强行当部分用）。
**两者之间没有"生命流转"的机制。**

什么时候短变长？什么时候长唤醒短？什么时候拆 MoE？什么时候从整体出发？

我的回答是**用"基于惊喜度（Surprise）的触发"代替定时器**——只有当系统遇到"强烈违背预测、或者极具启发性"的信息时，
才触发"突触可塑性"，把它压缩提炼（为道日损）写入长期。
日常对话阅后即焚，**不要污染长期记忆**。

部分 vs 整体则用**全局工作空间理论（Global Workspace Theory, GWT）**来调度：
- 简单确定的任务（翻译、算术）→ 唤醒局部专家，低能耗、无意识状态。
- 跨领域、充满矛盾、需道德判断的任务 → 局部专家的结论广播到全局共享空间，高能耗、有意识状态。

## 四、工程化：把手弄脏

到这里哲学框架已经搭起来了。但**纸上得来终觉浅**——必须亲手做一个可证伪的 Toy Model。

我跟 Gemini 一起把宏大概念"降维"成四步工程路线图：

### 第一步：变与不变的基础架构

- 选一个 1B 量级、逻辑能力强的小模型（最后选了 Qwen2.5-0.5B 和 3B），**所有参数彻底冻结**。
- 注入一个随机初始化的 LoRA（r=4 或 8）——这就是物理上的"留白专家"。

### 第二步：高维解耦——Latent Prefix Injection

不让 LoRA 直接参与生成 Token。设计一个小的 MLP"思考生成器"，
把 LoRA 的输出变成 K 个**连续的、高维的浮点向量**，直接拼接到用户输入的 Embedding 前面。
（Coconut 风格的连续思维循环。）

这步解决的是"留白模块的思考不被强制降维成文字"。

### 第三步：过程大于结果——重塑 Loss

不再用 Cross-Entropy（预测下一个词）。用 **MSE 蒸馏中间层隐状态**——让"留白模块"在处理问题时，
其内部高维隐状态要尽可能对齐"底座看过正确推理时的内部隐状态"。

只要脑电波对了，即使嘴瓢说错了答案，Loss 也下降——**在学"怎么思考"，不是"背诵答案"**。

### 第四步：为道日损——睡眠巩固

- **白天（日益）**：用户对话历史存到 KV Cache / JSON（短期情景记忆）。
- **夜晚（日损）**：系统空闲时启动"提炼网络"，把短期记忆通过自编码器压缩成专属于该用户的极小 LoRA 更新。
- **第二天**：清空昨天的 KV Cache，只加载被"日损"过的 LoRA（长期语义/逻辑记忆）。

## 五、实验验证：把哲学命题变成可测量的曲线

工程路线图搭好之后，我用了大约一年的时间（2026 春–夏），
把它变成 5 个**有 ground truth、能被线性探针测量**的子项目。
这个仓库里 `agi_demo/FINDINGS_*.md` 是完整报告。下面是浓缩版——也是我回过头来**验证/修正**前面那些哲学思考的过程。

### Project 1（0.5B + LoRA + Coconut）：冷启动不是 Bug，是教育方式错了

- **问题**：frozen 底座 + LoRA 留白 + 连续思维循环，能不能学会多跳推理？
- **结论**：
  - 均匀难度训练 → **Latent 通道学废了**（潜在推理的 B/C 都坍缩到 chance，而直接 baseline A 正常学）。
    探针显示第一步 thought 向量确实编码了第一个中间值（B x1=0.57 vs 0.10 chance），但推理链在第 1 步后就死了。
  - 换成**能力门控课程（shallow→deep, competence-gated）** → 一切都救回来了。
    - 潜在推理 (B) 在 OOD 深度上**反超**直接 baseline：hops-5 准确率 0.52 (B) vs 0.34 (A)。
    - **过程监督 (C)** 在 ID 深度上最强：hops-3 0.93，hops-4 0.76。
    - 探针显示 thought x1 和 x4 **都被线性可解码**（C: x1=1.00, x4=0.81）——真的学到了多步潜在结构。
- **我学到的**：直接验证了哲学那段的判断——"变"模块不是天生弱，是**脆弱的训练方式**把它掐死了。
  正确的态度是给它"课程"——先 shallow 学会基础动作，再 deep 拓展能力。这跟教育小孩一样。

### Project 2（3B 规模）：过程监督是"潜在推理划算"的前提

- **问题**：规模放大到 3B，结论还成立吗？
- **结论**：
  - 出现**规模反转**：0.5B 时 latent > 直接 baseline；3B 时**反过来**，plain latent (B) 在 OOD 上比 A 更差（hops-7: 0.60 vs 0.84）。
    原因是强底座自己就能解训范围，latent 通道没人管就学了**只编码最终答案的捷径**。
  - 但加上**过程监督**之后一切又翻了回来——C 在 OOD 上击败 A（hops-7: **0.90** vs 0.84）。
  - **贯穿所有 arms 和所有规模的"万有定律"**：
    > **OOD 泛化 ⇔ 推理链中有多少中间步骤是线性可解码的。**
- **我学到的**：在 AGI 这个规模上，**过程监督不是装饰，是命门**。
  没有过程监督，潜在空间只会塌成"答案缓存"。

### Project 2b（因果消融）：监督 ↔ 因果 ↔ 可解码性

- **问题**：只改"哪几步潜在步骤受过程监督"，效果怎么变？
- **结论**：从无监督 → 深监督 → 浅监督 → 全监督，**OOD 准确率单调上升**；探针的可解码性也单调上升。
  跨任务（perm）成立，量级有种子噪声，但方向稳定。
- **我学到的**：这是"过程 > 结果"哲学命题的**因果性证据**——监督不是相关性，是真正的因果机制。

### Project 3（frozen + 外挂记忆）：一个干净的负结果

- **问题**：给 frozen Transformer 加一个 attention-addressed 的 latent memory（多个 slot、可寻址、可读写），能不能用？
- **结论**：
  - 写 ✓（slot-probe 0.62）
  - 寻址 ✓（argmax attn = 正确 slot 的概率 0.72）
  - 读 ✓（read-probe 0.69）
  - **用 = 0.10 = 随机**
  - 想解冻来强制它"用"，底座直接崩盘。
- **我学到的**：**可观测 ≠ 可用**。一个 frozen Transformer 从未被训练过把"注入的 latent"当操作数。
  LoRA 的轻量调整装不进这种"接口"——你不能在一个静态的协议栈上塞一个它不认识的 opcode。
  **这条结论直接改变了我的工程方向**：与其在 frozen Transformer 上打补丁，不如**从零做一个"记忆当操作数是原生"的小内核**。

### Project 4（自研 fast-weight kernel）：从一个失败的诊断长出真正可用的东西

- **问题**：既然 frozen Transformer + 外挂记忆行不通，能不能做一个根本就不是 Transformer 的小内核，让"记忆当操作数"是它与生俱来的能力？
- **结论**：
  - 每个层带一个**固定大小矩阵状态 S**（fast weight / linear-attention associative memory）。
    没有 token 间 attention，没有 softmax，没有 growing KV cache。
  - 每个 token，从隐状态 h 算 k/v/q，然后：
    ```
    S ← γ·S + β·(v − S k) kᵀ    # delta-rule associative write
    r = S q                       # READ 在 cell 内部完成
    out = h + W_o r
    ```
  - 关键：**read 直接是 cell 的产物**，不是"从外部塞进去"的——这就解决了 Project 3 的根本问题。
  - **多时间尺度层级**：L 层，γ 散布在 [0, 0.7, 0.95, 0.99]。快层是题内工作记忆，慢层是 session 长程记忆。
  - **Project 3 的 `USE=0.10` 提升到 `ref_acc=1.00`**。8-config 矩阵，5-seed 跑通，±0.000 鲁棒。
- **我学到的**：
  - 当一个方案"差一点点就成"时（写 ✓ 寻址 ✓ 读 ✓ 但用 = 0.10），**继续打补丁是错的，要换架构假设**。
  - 真正的"分层记忆"是**多个时间尺度的天然结构**，不是后处理加上去的。
  - 这个 kernel 验证了哲学那段的预测——"分层 KV Cache + 高维操作数"确实是真东西。

### Project 5（巩固循环，B200 上进行中）：把"为道日损"工程化

- **问题**：Project 4 解决了"潜在记忆当操作数"的问题，但每次都是"单 session、不覆盖"。
  真实场景里，**同一个 slot 会被多次覆写**——Hebbian 和 delta-rule 在覆写下的差异到底有多大？
- **结论**（Phase A 已完成，B200 上 14-config 矩阵）：
  - delta-rule 的优势是**真实的**，但只体现在**最深的覆写深度**上；
  - 表现方式不是均值差异，而是**鲁棒性（零方差）**——delta-rule 在所有 seeds 上稳定，Hebbian 在覆写下退化。
- **Phase B / 完整 Project 5**：sleep consolidation → bAbI 风格实体追踪。进行中。

## 六、回头看：这一年我到底想了什么

把这份思考记录和实验结果摆在一起看，**我之前那些哲学直觉哪些对了、哪些被现实打了脸**：

### 对的

1. **"留白"必须是结构上的，不是补丁上的**。LoRA 这类低秩改造在"满"上做文章，对冷启动太敏感。
   真正可行的是 **Project 4 那种从零设计的、记忆当操作数是原生的内核**。
2. **过程监督 > 结果监督**。Project 1/2/2b 三轮实验（0.5B、3B、因果消融）一致支持这个判断。
3. **OOD 泛化 ⇔ 中间链可解码性**。这是 Project 2 给我的"万有定律"——比任何"涌现"故事都更可证伪、更可测量。
4. **可观测性是研究的支柱**。Project 3 的失败教会我：**没探针就只能讲故事**。有探针你才能区分"模型没学"和"模型学了但没暴露"。
5. **架构假设错了要回头换，不要在错的假设上修修补补**。Project 4 的诞生本身就是这个原则的胜利。

### 被修正的

1. **MoE 的"冷启动"可以靠教育方式解决**——但不是"课程"层面的"shadow mode / 好奇心路由"那种工程 trick。
   Project 1 的能力门控课程只是部分答案；Project 3 揭示了**架构本身如果不支持，路由怎么改都没用**。
2. **"为学日益"那一步我们做得太多了**。预训练堆 100B+ token 是过度学习，真正的"道"远小于这个。
   但**如何"日损"出那几 B 的精华，Project 5 还在做**——这是整条路最缺的一环。
3. **"高维解耦"不是接口替换**。我原来以为"让两个模型直接传 latent 向量"就能绕过降维。
   现在看 Project 3 的诊断：即使 latent 向量被读出来了，**frozen 底座也不会"用"它**。
   解耦不只是改接口，是**改架构让"用"是原生的**——这是 Project 4 的核心教训。

### 还没想明白的

1. **巩固 / "日损"**。怎么从一天的对话里可靠地提炼出"几 B 的个性化 LoRA"？这是 Project 5 的 Phase B 想回答的，但目前还没结果。
2. **"全局工作空间理论"在工程上长什么样**。短期/长期、部分/整体的时间触发和空间调度，目前还停留在概念层面，没有可跑的 baseline。
3. **规模问题**。Project 4 是在 0.5B 量级 + 小内核（d_model=128, d_state=64, 4 层）上验证的。放大到几 B、几十 B，原生记忆的容量和稳定性是不是还成立？还没测。
4. **与现有生态的接口**。这个 kernel 现在是孤岛。怎样把它和 LLM 的能力（语言理解、世界知识）接起来？RAG 显然不够。
