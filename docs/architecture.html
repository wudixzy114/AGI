01

统一框架 — 带巩固的记忆层级

三个"看起来独立的功能"其实是一套系统：不同时间尺度的记忆，加上把短期固化成长期的巩固通路。稳定-可塑性权衡被显式拆成了"冻结基座 + 可塑留白"两半。

① 工作记忆 / 计算WORKING MEMORY
连续思考回路（Coconut 式） — 隐状态回喂 thought_proj，在连续空间里推理若干步，不塌缩到离散 token。
② 短期记忆SHORT-TERM
可寻址记忆槽 LatentMemory — 一个 session 内 T 道题共享，起始清零（"留白"），逐题写入、跨题读取。
③ 巩固 短→长CONSOLIDATION
过程监督（arm C） — 让每个中间步骤可被解码，把"过程"钉进可塑权重。（未来：sleep 离线蒸馏 → 写回长期）
④ 长期记忆LONG-TERM · FROZEN
冻结的 Qwen2.5 基座 — 训练中一个参数都不动，是稳定的知识底座。可塑性全部外置，避免灾难性遗忘。

03

三条实验臂 — 同一个类，不同监督

同一个 CoconutReasoner，靠 n_latent 与损失项区分三条臂。这是用来做消融、验证"过程 > 结果"的对照组。

RESULT-ONLY

A 只给答案

n_latent = 0。读完 "=" 直接解码答案，没有隐思考步。纯结果基线，只训练 LoRA。

0.5B: 1.08M 参 · 3B: 3.69M 参

LATENT

B 隐思考 + 答案

隐思考 hops 步，只用"最终答对没有"隐式奖励过程。加入 thought_proj。

0.5B: 4.30M 参 · 3B: 20.47M 参

LATENT + PROCESS

C 隐思考 + 过程监督

在 B 之上，用 step_head 要求第 i 步思考向量预测中间值 xᵢ。显式的"过程 > 结果"监督。

0.5B: 4.30M 参 · 3B: 20.49M 参

已被因果证实的核心结论：过程监督 → 中间步骤"可被线性探针解码" → OOD 泛化。消融只改"哪些隐步受监督"，OOD 单调上升（无 0.60 < 深半 0.69 < 浅半 0.79 < 全 0.90），探针精确镜像。跨任务（perm 查表）同样成立。
04

记忆回路（Project 3）— 读是怎么接入的

核心手法：不改基座内部，而是在输入 embedding 序列最前面多塞一个"记忆 token"。基座根本不知道这多出来的位置是记忆——对它来说只是序列多了一个 token。forward_problem() 里，一个 session 的 T 道题共享同一组记忆槽。

读取 · 三步

1

构造 query — 均值池化

query = mean_pool(emb · mask) # (B, H)

拿当前这道题的 token embedding 平均成一个向量，当作"我要查什么"。

2

软寻址 — attention over slots

logits = (q · slotsᵀ)/√H # (B,M) attn = softmax(logits) read = Σ attn · slots # (B,H)

不是"取第 k 个槽"，而是对所有槽加权平均。全并行、可微，没有串行扫描 —— 直接回应了"记忆读写必须可并行"这条约束。

3

翻译 — decode & re-embed

probs = softmax(slot_head(read)) soft = probs @ 冻结词表 # (B,H) inject = read + soft

冻结基座用不了裸隐向量，于是把 read 解码成数字分布，借基座自己的冻结词表变回"软 token"，基座才认得。

⬡ 接入点 · inject 拼到最前

读出的 inject 被当作序列第 0 个伪 token，拼在真实 token 之前；attention mask 同步补一位。之后每个隐思考步还会把 inject 反复加回，保证读出的值全程可用。

emb = cat([inject, emb]) # (B, L+1, H)
mask = cat([1, mask])
out = base(inputs_embeds=emb, mask)

✎ 写入 · 门控更新

每道题答完，把答案隐状态写进它的槽：new = (1−g)·old + g·v，g 是学出来的门。写投影同样近零初始化，起始温柔。

v = v_proj(ans_hidden)
g = sigmoid(gate(ans_hidden))
slots[write_slot] = (1−g)·old + g·v

05

和原来"单层 Embedding"的本质区别

表面上两者最后都变成 (B, ?, H) 喂给基座，但性质完全不同：一个是静态无状态查表，一个是有状态的软检索。

维度原来 · self.embed(input_ids)新增 · memory.read(query)
信息来自哪当前输入文本的 token id之前题目写入槽里的答案 — 引用题里根本没有那个数字
寻址方式硬查表：id → 词表第 id 行软寻址：query 与所有槽算相似度，softmax 加权和（连续可微）
状态无状态。同一 id 永远查出同一行有状态。每 session 清零，逐题写入、跨题演化
可训练词表冻结，不训练q / r / v / gate 投影都可训练（属于"留白"）
对基座是否"母语"是。天然就是它自己的词表向量不是。是"外来"向量，必须翻译回词表空间才肯消费
最深的一层差别：embedding 出来的东西天生是基座的"母语"，而记忆读出来的是"外语"。这正是第 3 步 decode-and-re-embed 存在的原因，也是记忆这条线比隐推理更难调的坎——多了一道"让冻结基座接受外来信息"的关。
06

诚实的现状 — 哪些成立，哪些还没跑

架构完整不等于结论成立。这里区分已被多种子/因果消融证实的、已被撤回的、以及代码就绪但还没有结果的部分。

✓ 已证实
  • 课程学习救活隐推理：均匀难度下 B/C 塌到随机，浅→深课程后才活。
  • 过程监督 → 可解码 → OOD 是因果的：消融 + 探针镜像，最硬的结论。
  • 跨任务稳健：perm 查表上 A/B 随机、C 保持 3× chance。
  • 0.5B 与 3B、多种子（error bar）均复现。
⟳ 已撤回 / 需谨慎
  • "3B 规模反转、隐推理更差"是单种子假象；多种子下 A ≈ B。
  • OOD 的绝对幅度对种子敏感，需 ≥5 种子；in-dist 无噪声。
  • 残差 ≠ 课程：残差修可训练性，但只有课程给出干净可解码链。
○ 代码就绪 · 未验证
  • Project 3 记忆机制：outputs/ 里还没有任何 session/memory 结果。
  • diag_read.py 透露正卡在："读得出（可解码）但冻结基座用不了它"。
  • read + soft_read 双通道是为绕过该 bug 刚加的方案，尚未跑通。
两个悬而未决的 crux： (A) 自进化的驱动信号 — 没有 grounding 锚点，迭代自训练会塌；任务的可验证答案是天然锚点。 (B) 可观测性 — 隐推理 + 漂移权重 + 隐记忆三者叠加会共同摧毁探针方法论，必须从设计上守住"槽/思考向量可被线性解码"这条红线。
